# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| 1.0.x | ✅ Supported |
| < 1.0.0 | ❌ Not supported |

## Reporting a vulnerability

Please do not open a public issue for security vulnerabilities.

Use one of the following private reporting channels:

- GitHub Private Vulnerability Reporting (preferred): open the repository Security tab and submit a private report.
- Email: 188705139+M003aad@users.noreply.github.com

When reporting, include:

- A clear description of the issue
- Steps to reproduce or a proof of concept
- Affected version and extension build information
- Any related impact or risk assessment

## Response expectations

We aim to acknowledge valid reports within 5 business days and to provide a remediation timeline as soon as the issue is triaged. For confirmed vulnerabilities, we will work to release a patched version as quickly as practicable and may coordinate disclosure timing with the reporter.

## Security best practices

- Keep your browser and extension installation updated.
- Run the extension only from trusted sources.
- Avoid loading locally modified or unsigned builds in production environments.
- Review the whitelist and account rules before using them in shared or managed browsers.

## Reporting process summary

1. Submit a private report via GitHub Private Vulnerability Reporting or email the security contact.
2. Wait for acknowledgment and triage.
3. Work with maintainers to reproduce, validate, and fix the issue.
4. Receive a coordinated disclosure or patch release when the fix is ready.
